Roadmap Where the project is heading

Roadmap from book to small automation platform.

The first version of Reporting Forge is a book and lab. Future versions may wrap the same patterns into a small, opinionated platform for running reporting workflows. This page sketches that path so expectations stay clear.

Phase 1 - Book and lab (now)

  • Design the 30 day curriculum from manual spreadsheets to Python and Power BI.
  • Ship example scripts and sample data that run on a normal Windows laptop.
  • Test the labs with early readers and refine based on real reporting pain.

Phase 2 - Sharper patterns and shared helpers

  • Extract common helpers for validation, logging, and scheduling from the labs.
  • Publish small, reusable Python modules that work with or without any future platform.
  • Collect example workflows from readers in different industries.

Phase 3 - Light orchestration layer (exploratory)

  • Explore a minimal way to describe and run workflows built in the lab.
  • Keep the core principle that you own your scripts and data; the platform only orchestrates.
  • Decide whether this should be open source, hosted, or both.

Any future platform work will stay grounded in the same goal as the book: make reporting feel boring and dependable instead of fragile and stressful.

Roadmaps change as reality and feedback show up. This page is a living document rather than a fixed promise.

Guiding principles
  • Teach patterns first, build tooling later.
  • Stay small and understandable rather than clever and opaque.
  • Let people keep the tools they already like.
  • Use AI as a helper, not a replacement for judgment.
How to influence the roadmap

If you have strong reporting pain and are willing to share examples, that feedback will have more impact than any abstract feature request. Email hello@reportingforge.com with a short summary of your world.
